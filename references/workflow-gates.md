# Workflow Gates — 5 步闸门细则

> 每个被 generate-front-business-skills 生成的 skill,**必须**包含这一节。本文件是细则参考,
> SKILL.md 中按需摘抄,不要求逐字照搬,但关键词与顺序不可变。

---

## 1. 共识(Consensus First)

**目的**:动手前消除歧义。

**做法**:

- 把目标、行为、边界、不改什么,**逐条**写出来
- 一次仅问一个问题
- 用户**显式确认**("OK / 按此执行 / 继续")之后才进入下一步

**闸门**:用户确认或写明「按此执行」之前,禁止写测试和实现。

---

## 2. 架构预检(Architecture Preflight)

**目的**:落点 + 风险先看。

**做法**:

- 读工程既有规则(`CLAUDE.md` / `.cursor/rules/*.mdc` / `.claude/skills/` / `.cursor/skills/`)
- 用只读工具扫:`pwd`、`ls src/`、`package.json`、分层目录、`du -sh` 体积
- 判断:新代码应该落在 `apps / core / shared / services / utils` 哪一层
- 跨包改动 → 必须列改动点 + 影响面 + 风险

**闸门**:输出简短预检结论(目标包、风险、是否触发业务梳理规则)。

---

## 3. TDD 红绿重构(Red / Green / Refactor)

**目的**:用测试驱动可复用业务逻辑。

**做法**:

- 红:先写失败测试(`local-tests/` 镜像源码结构)
- 绿:最小实现让测试过
- 重构:去重 / 分层 / 命名,测试保持绿

**闸门**:测试全绿、覆盖主路径 + 边界 + 错误降级。

---

## 4. 跑完即删(Cleanup Local Tests)

**目的**:不留测试残留。

**做法**:

- 测试通过后,删除本次为 TDD 新建的 `local-tests/` 文件
- `git status` 应见不到 `local-tests/` 下的本次新增
- 若项目要求保留,把用例迁到正式 `__tests__/` 或 `tests/`

**闸门**:`local-tests/` 干净(或迁移完成)。

---

## 5. Lint(Lint After Edit)

**目的**:保证代码准确性 + 风格一致。

**做法**:

- 跑工程 lint(`pnpm lint` / `npm run lint`)
- 跑格式化(`prettier --write` / 工程约定)
- 跑类型检查(`tsc --noEmit` / 工程约定)

**闸门**:lint 0 error,警告按工程规则处理(全清 / 留下注释说明)。

---

## 闸门链强制顺序

```
共识  →  架构预检  →  TDD 红绿  →  跑完即删  →  Lint
```

**不可跳、不可换序、不可并行。** 任一闸门失败 → 回到该闸门修复,不进入下一步。

---

## 运行时怎么注入(省 token)

停步条文**只写进** `cursor-rule.mdc`,并复制到 `<project>/.cursor/rules/<slug>.mdc`(`alwaysApply: true`)。这是每轮都会注入的那一份,必须短。

产物 `SKILL.md` 标题后只留指针,不把同一段再抄一遍,也不再单开「强制工作流」索引或「多轮一对一问答」。具体问题并进第 1 步,一次只问一个。

`SKILL.md` 只补充本工程主栈的落点、测试命令、lint 命令。禁止把 12 栈全表、同步脚本、安装教程写进产物。

```markdown
## 运行时执行协议(强制,先于任何写操作)

每轮第一行:`当前闸门: N/5 <共识|架构预检|TDD 红绿重构|跑完即删|Lint>`。
停步条文在 `.cursor/rules/<slug>.mdc`,每轮已注入,此处不重复。未过当前闸门禁止写文件。
```

## Cursor 常驻规则(默认必写)

```markdown
---
description: 写代码前按 5 步闸门停步,未确认禁止写文件
alwaysApply: true
---

# <slug>

每轮第一行:`当前闸门: N/5 <共识|架构预检|TDD 红绿重构|跑完即删|Lint>`。不可跳步、不可换序。

1. 共识 — 四行:落点、行为、边界、不改什么。有歧义或字段/接口入参不清楚,只问一个问题并停止,禁止猜。未得到「OK / 确认 / 按此执行 / 继续」前禁止写文件。本条已写明「按此执行」时,贴完四行可进第 2 步,仍不写实现。
2. 架构预检 — 只读。三行:目标包、风险、是否梳理业务分支。有歧义只问一个问题并停止。禁止写文件。
3. TDD — 先失败测试,再最小实现,再重构。无失败测试不写实现。覆盖主路径、边界、错误降级。降级或延后时按技能里的环境状态执行。
4. 跑完即删 — 删除本次 `local-tests/`。有残留不进下一步。
5. Lint — 跑本栈 lint 与已启用的类型检查。0 error 才算完成。

只改共识里的落点。任一闸门未过,停在该闸门。
```
