# Interview Questions — 询问清单与提问模板

> 配合主 SKILL.md 第 3 节使用。每个问题用一段"提问话术 + 备选 + 确认要点"。
> 铁律:**一次仅问一个问题**,用户显式确认后才记录。

---

## Q1 · 目标与触发场景(**预填默认**,只需二选一)

> ⚠ **本生成器的"原始目标"是固定的**——专用于"协助用户使用 AI 工具编写业务代码"。
> 本题**不需要每次重新设计**,只问用户"沿用 / 自定义"。

**预设目标(generate-front-business-skills 的原始目标,见主 SKILL.md "## 原始目标")**

```
目标:    协助用户使用 AI 工具编写业务代码
场景:    团队/个人希望把"用 AI 写代码"的最佳实践固化为可复用的 skill
产出:    一个强制 5 步闸门(共识 → 架构预检 → TDD → 跑完即删 → Lint)的 skill
```

**预设四类产出**

| 类别 | 典型例子 |
|---|---|
| **代码编写规范** | 命名约定、目录结构、风格统一、注释规则、错误处理规范 |
| **工程流程固化** | 架构预检、TDD 红绿、Code Review、PR 提交流程、bug 修复流程 |
| **最佳实践沉淀** | 业务分支梳理、改动影响确认、技术栈适配、跨端平台分支 |
| **AI 工具落地** | 触发命令、扫描提示、错误提醒、与编辑器(Claude Code / Cursor / Codex)集成 |

**提问话术**

> 本生成器的原始目标已固定为"协助用户用 AI 工具编写业务代码",四类产出见上。
> 这次你要:
> - **(A) 沿用默认**(推荐)—— 直接进入下一题(命名)
> - **(B) 自定义** —— 这个 skill 是为了解决什么**特定**的重复问题?在什么场景下被触发?

**确认要点**

- 选 A → 记下"沿用默认目标",进 Q2,**不再追问 Q1**
- 选 B → 按下方"自定义回答形式"展开,记入后再进 Q2

**自定义回答形式**(选 B 时使用)

```
痛点:   ...
触发:   ...
产出:   ...
```

**为何不每次问**

原始目标是本生成器的元定位,不是单个 skill 的细节;
若每次都让用户重述一遍,反而稀释了"用 AI 写代码"这一核心一致性。
只在用户明确说"这次要换个方向"时,才展开追问。

## Q2 · 命名(slug)(**预填 `business-coding-flow`**)

> ⚠ **预填默认**:本生成器产物默认名 `business-coding-flow`(业务编码流程),
> 选"沿用"即跳过;用户可指定其他 slug。

**提问话术**

> 产物默认名:`business-coding-flow`(业务编码流程,本生成器预设)。
> 会作为目录名。
> - **沿用**(推荐)—— 直接进入下一题
> - **自定义** —— 给出新的 kebab-case slug(给 3 个候选 + 自由输入):
>   - `<topic>-helper`
>   - `<verb>-<object>`
>   - `<topic>-workflow`

**反模式**

- 含大写、下划线、空格、中文
- 与 `.claude/skills/` 或 `.cursor/skills/` 下已有 skill 重名(扫描阶段已查)

**确认要点**:用户输入或选定的 slug 全小写、无分隔符异常、≤ 64 字符。

## Q3 · 一句话描述(用于 frontmatter `description`)

**提问话术**

> 用一句话写它的 description。会出现在 skill 列表里,用户据此判断要不要触发。
> 建议包含:**触发场景 + 产出形态**。

**模板**

```
<动词> <对象>,<触发场景>。<产出或效果>。在<信号词>时使用。
```

**确认要点**:长度 ≤ 1024 字符、读起来能让人秒懂何时该用。

## Q4 · 核心阶段数与阶段内容

**提问话术**

> 它的工作流有几个阶段?每阶段是什么?
> (空工程默认采用 5 步闸门;已有约定的工程,沿用工程约定。)

**默认 5 步闸门**(必须照搬顺序)

```
1. 共识
2. 架构预检
3. TDD 红绿重构
4. 跑完即删
5. Lint
```

**若用户给自定义阶段**

- 至少 3 个,最多 7 个
- 每个阶段都要有:**输入 / 处理 / 输出 / 闸门条件**
- 一阶段一次问完,再问下一阶段

**确认要点**:阶段数确定后再逐阶段追问输入输出。

---

## Q5 · 各阶段的输入 / 输出 / 门禁(逐阶段)

**提问话术**(针对当前阶段 X)

> 阶段 `<X>`:
> - **输入**:这一阶段拿到的材料是什么?(前置产出、上游文件、用户消息)
> - **处理**:做什么动作?(扫目录、写测试、跑命令、问问题)
> - **输出**:完成后留下什么?(文件、共识摘要、测试结果)
> - **闸门**:通过条件是什么?(用户确认 / 测试绿 / lint 0 error)

**反模式**

- 输入输出模糊("做一些事情")
- 闸门不可验证("差不多就行")

## Q-Editor-Sync · 多处复用策略(仅当选了 ≥2 个编辑器时问)

**提问话术**

> 多处复用时,怎么处理文件统一性?(一次仅答一项)

**选项**

- **(A) 一源多端部署**(推荐)—— 主源在 `<统一源路径>`,生成器在最终落盘时**自动复制**到每个选中的编辑器目录;后续编辑只改主源,再用 `scripts/sync.ps1` / `scripts/sync.sh` 同步
- **(B) 软链接 / junction**(Windows:mklink /J,Linux/macOS:ln -s)—— 主源放一处,各编辑器目录创建符号链接指向主源(零复制,实时同步)
- **(C) 每端独立副本** —— 每个编辑器一份,各自维护(用户自己保证一致性,生成器不负责同步)
- **(D) 主源 + 每端一份 wrapper** —— 主源放完整 SKILL.md,每个编辑器目录只放极简 frontmatter + 链接指回主源

**前置问题**(选 A / D 时问)

> 统一源路径定在哪?(一次仅答一项)
> - 桌面:`C:/Users/37313/Desktop/<slug>/`(本生成器默认)
> - 用户级 skills 根:`C:/Users/37313/skills/<slug>/`
> - 项目级:`<project>/.skills-source/<slug>/`(隐藏在 `.skills-source/`,避免 IDE 误扫)
> - 自定义:Other 输入
